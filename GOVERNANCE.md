# Governance

MCP Sentinel is maintained in the open. Maintainers merge ordinary changes after review and passing checks. Enforcement, authentication, approval, audit/signing, and sandbox changes require review from two maintainers when the project has enough active maintainers.

Major architectural changes use an ADR and a public discussion period. Protocol claims must cite the stable specification and match executable tests. Security embargoes are handled privately until a coordinated release.

Maintainers may be added after sustained, constructive contributions and demonstrated security judgment. Inactive maintainers may move to emeritus status. Conflicts are disclosed; a conflicted maintainer recuses from the decision. If consensus fails, a simple majority of non-conflicted active maintainers decides, with rationale recorded publicly unless security-sensitive.
